# Data model

Presentations belong to a workspace user. The presentation row holds the canonical intermediate representation (IR), request settings, lifecycle state and optimistic revision. Immutable snapshots preserve saved revisions. The document schema version identifies the IR format. The presentation revision tracks saves and is used for edit conflict checks.

The IR stores optional deck design rules, sources, and slides with notes and source IDs. Each slide uses normalized coordinates mapped to the physical dimensions of its 16:9, 4:3 or 1:1 page. Elements are typed as text, shapes, images, lines, tables, charts or groups. Diagram nodes and arrows are composed from these existing element types. Tables can carry styles and numeric-column metadata. Charts can carry palettes, value labels and stacked series. The running API exposes the schema at `/api/v1/schemas/presentation`.

Generation jobs carry the next checkpoint, context and lease. Events use increasing numeric cursors and a configurable replay and retention window. Questions and submitted answers are persisted in the job context. Uploaded and generated assets are scoped to their owner and stored by generated key. Bundled Lucide icons resolve to PNGs without an upload record. The skills catalog combines shared seed recipes and user-owned manifests. A branded skill stores layout and placeholder metadata and references the original PPTX asset. Deleting a custom skill hides it from the catalog while preserving it for presentations that already use it.

Preview records connect generated slides to stored PNGs by fingerprint. A preview request reuses the PNG when its fingerprint matches and renders on demand when the fingerprint changes or the stored object is missing. Export records associate stored PPTX or PDF objects with the presentation revision, title and format. Artifact jobs capture the requested snapshot, claim, attempt count and result. Asset references record the owning deck or skill and the document, version or checkpoint that holds the reference. Pending object deletions survive process and storage failures.
